# Mind Spark 2026

Frontend event registration website for the National Engineers Day Special technical competition.

## Supabase setup

1. Create a Supabase project.
2. Open the Supabase SQL Editor and create the table:

```sql
create table public.registrations (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  team_id text not null unique,
  team_name text not null unique,
  captain_name text not null,
  captain_phone text not null,
  captain_email text not null,
  department text not null,
  branch_semester text not null,
  member_2 text not null,
  member_3 text not null,
  member_4 text not null
);
```

3. Run all of [supabase-fix.sql](supabase-fix.sql) in the Supabase SQL Editor. It repairs the table, creates the public RPCs, enables Row Level Security, and allows only authenticated Supabase users to access the dashboard data.

```sql
alter table public.registrations enable row level security;

create policy "public can register"
on public.registrations for insert
to anon
with check (true);

-- Do not add an anon SELECT policy. Run supabase-fix.sql to create the
-- restricted RPC functions used by the website instead.
```

The public page only requests a count, submits through the validated `register_team` RPC, and looks up a matching team by Team ID and Captain Email. It never requests the full directory.

## Create the admin account

1. In Supabase, open **Authentication / Users** and create the organizer user with email and password.
2. Keep public sign-ups disabled in **Authentication / Providers / Email**, and use the organizer account for `admin.html`. The dashboard data policy requires a valid Supabase login; anonymous users cannot read registrations.

If you previously added an `app_metadata.role` update, it is no longer required for the dashboard query after running the latest repair script.

For an optional role marker, run the following, replacing the email:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'organizer@example.com';
```

3. Sign out and sign in again on `admin.html` so the new JWT contains the admin role.

## Paste the Supabase keys

Open [script.js](script.js). At the very top, replace only these two values:

```js
const SUPABASE_URL = "PASTE_SUPABASE_PROJECT_URL_HERE";
const SUPABASE_ANON_KEY = "PASTE_SUPABASE_PUBLISHABLE_KEY_HERE";
```

Paste your Supabase Project URL into `SUPABASE_URL` and your browser-safe Publishable/Anon key into `SUPABASE_ANON_KEY`.

Open [admin.js](admin.js) and paste the same two values at the top of that file. Never paste a `service_role` key into either file.

## Run locally

Open `index.html` in a browser. Use `admin.html` for the registration desk. A local web server is recommended when browser security blocks CDN requests from a `file:` URL.

The registration flow generates sequential IDs from `MS01` through `MS30` inside one locked database transaction, rejects duplicate team names, blocks submissions after 30 teams, disables the button while submitting, and shows a success popup with the Team ID.

From PowerShell:

```powershell
Set-Location 'event registration'
py -m http.server 8000
```

Open `http://127.0.0.1:8000/`. Deploy the folder to a static host for a public QR-code URL. Keep the publishable Supabase key in the frontend; never expose a `service_role` key.

## Production checklist

- Run the latest `supabase-fix.sql` after every database change.
- Test one registration and confirm it appears in the admin dashboard.
- Test a duplicate team name and confirm it is rejected.
- Test the lookup with the returned Team ID and captain email.
- Test the admin login, search, department filter, refresh, CSV export, Excel export, and delete confirmation.
- Use HTTPS on the deployed site and configure the deployed URL in Supabase Authentication redirect settings.
